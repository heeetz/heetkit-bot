# HeetKit v1.4.1

HeetKit now supports a headless Linux/Docker Server alongside Windows Desktop,
with private browser management, persistent operation modes and saved channels.
These changes build on the previous stable release, v1.3.0.

## What's New

- **HeetKit Server:** Run the shared backend without a desktop window in native
  AMD64 or ARM64 containers, with a persistent profile for settings and authorization.
  Windows Desktop keeps its local window, tray controls and AI Playground.
- **Private browser management:** Configure Twitch and OAuth, commands, AI,
  filters and credentials from an authenticated panel. Remote access uses private
  Tailscale HTTPS or an SSH tunnel; no public management endpoint is required.
- **Persistent operation modes:** Always On, Stream Only, Manual and Disabled
  control Server connectivity across restarts. Manual starts stopped.
- **Saved Server channels:** Create, rename, update and delete named targets in
  Settings. Selecting or saving a preset leaves the bot unchanged; Switch explicitly
  applies it while retaining the bot account, credentials and valid OAuth.
- **Server command availability:** Limit built-in or custom commands to live or
  offline streams, independently of the connection mode. Anytime remains the default.
- **Configuration transfer:** Preview and import portable commands, personalities,
  AI preferences, filters and reactions between Desktop and Server. Secrets, OAuth,
  history, privacy opt-outs and the destination operation mode remain separate.

## Improvements & Fixes

- Manual broadcaster commands work when the same Twitch account runs the bot.
  Outgoing message IDs prevent response loops and accidental AI requests from
  command listings, including concurrent sends and EventSub replays.
- Public command help reflects enabled built-ins, aliases and custom commands.
- Built-in editors separate Enabled from aligned permission, availability and
  cooldown fields, with stacking on narrow screens and preserved keyboard controls.
- Clearer Server Twitch setup, browser OAuth completion and private diagnostics;
  improved local browser compatibility and configurable loopback management.
- Simpler primary/fallback model selectors, improved command focus and scrolling,
  and configurable Tg repeat limits with duplicate-burst protection.
- Updated runtime/build dependencies and CA trust, with native AMD64/ARM64
  container checks. pip's separately vendored urllib3 advisories remain documented
  in [Security](../../SECURITY.md#package-installer-limitation).

## Updating

Back up the existing profile first. Quit Windows Desktop fully through **tray Exit**
before installing or replacing portable files. Existing profiles, settings and
credentials remain compatible. Windows downloads are unsigned and retain the
existing .NET Framework and WebView2 requirements.

For Server, follow the [Docker update and backup procedure](../docker.md#backup-restore-and-updates):
stop the container, back up the whole persistent volume and external secrets privately,
retain the previous image, then rebuild/recreate with the same Compose project,
volume and architecture. Never delete the volume during an update. Manual and
Disabled stay disconnected after recreation. Keep Tailscale Serve private.
Run only one instance per Twitch bot account.

Windows binary publication remains subject to the recorded
[redistribution requirements](../../THIRD_PARTY_NOTICES.md#next-windows-build-corrected-materials-and-remaining-blockers);
passing build and notice checks alone does not resolve those obligations.
